# متجر العاقل — Telegram Mini App

## مهم قبل التشغيل
- لا تضع Bot Token داخل الكود أو ترسله لأي شخص. أنشئ رمزًا جديدًا من BotFather إذا سبق نشره.
- الميني آب يجب فتحه من داخل تيليجرام حتى تتوفر هوية المستخدم. النسخة الحالية تستخدم `initDataUnsafe` للواجهة فقط؛ قبل إطلاق تجاري عام أضف التحقق الخادمي من `Telegram.WebApp.initData`.
- أسعار النجوم ليست سعر صرف رسميًا ثابتًا بالريال. `SAR_PER_STAR` مجرد قيمة تقريبية تضبطها أنت، والسعر النهائي الذي يدفعه العميل هو عدد صحيح من النجوم.
- روابط التسليم يجب أن تكون روابط تملك حق مشاركة محتواها. روابط القروبات الخاصة قد تتطلب انضمامًا أو دعوة صالحة.

## الملفات
- `app.py`: API + بوت تيليجرام + قاعدة البيانات + الفواتير + الإدارة.
- `templates/index.html`: واجهة التطبيق المصغر.
- `static/style.css`: التصميم الأسود والذهبي والحركات.
- `static/app.js`: تحميل المنتجات، التنقل، النجوم المتحركة، وفتح الفاتورة.
- `requirements.txt`, `Procfile`, `render.yaml`: إعدادات النشر.

## تشغيل محلي
1. ثبّت Python 3.11 أو أحدث.
2. `python -m venv .venv` ثم فعّل البيئة.
3. `pip install -r requirements.txt`
4. عيّن متغيرات البيئة `BOT_TOKEN`, `ADMIN_ID`, `WEBAPP_URL`.
5. جهّز مسار قاعدة البيانات الدائم: `mkdir -p /var/data` (أو عيّن `DB_PATH=./alaqil.db` محليًا).
6. `python app.py`

## نشر Render
1. ارفع المجلد إلى مستودع Git خاص واربطه بـ Render.
2. أنشئ Web Service من `render.yaml` أو أدخل إعداداته يدويًا.
3. اضبط `BOT_TOKEN` كـ Secret، و`ADMIN_ID`، و`SAR_PER_STAR`.
4. بعد أول نشر، انسخ رابط HTTPS للخدمة وضعه في `WEBAPP_URL` ثم أعد النشر.
5. في BotFather اضبط زر القائمة / Mini App ليشير إلى رابط الخدمة، وأضف نطاق HTTPS إلى إعدادات Web App.
6. للحصول على تشغيل مستمر وتخزين دائم، استخدم خطة Render مدفوعة مع disk أو بدّل قاعدة البيانات إلى Render Postgres. الخطة المجانية قد تنام وملفاتها المحلية مؤقتة.

## الإدارة
- أرسل `/admin` للبوت من حساب `ADMIN_ID`.
- إضافة منتج: الاسم → السعر بالريال → الوصف → صورة مرفقة → رابط التسليم → تأكيد.
- يمكن إخفاء المنتج من قائمة المنتجات. إخفاء المنتج لا يحذف سجل الطلبات.
- الرسائل الجماعية تذهب فقط إلى المستخدمين الذين بدأوا البوت مسبقًا.

## ملاحظات قبل استقبال أموال حقيقية
هذه نقطة بداية قابلة للتطوير وليست تدقيقًا أمنيًا أو ضمانًا خاليًا من الأخطاء. اختبر الدفع في بيئة اختبار أولًا. أضف التحقق الخادمي من `initData`، ومعالجة تكرار `successful_payment` بشكل idempotent، ومراجعة الروابط وصلاحيات التسليم، وسياسة دعم/استرجاع، قبل إطلاق المتجر تجاريًا.
